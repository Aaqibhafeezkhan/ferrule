# Protobuf wire-decoder fuzz target

A standalone [cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz) harness for
the public binary reader in `crates/format-protobuf`
(`format_protobuf::from_slice`). It is not a member of the root workspace: the
empty `[workspace]` table in `Cargo.toml` makes this directory its own
workspace with its own `Cargo.lock`, so root builds, tests and CI never compile
it.

## What it checks

Each input is decoded against five roots from two small, self-authored schemas
in `src/lib.rs`:

| Root | Covers |
| --- | --- |
| `fuzz.wire.Root` | nested messages, repeated messages, a three-way `oneof`, `map<string, int32>`, `map<int64, Leaf>`, `map<bool, Color>`, field number 536870911 |
| `fuzz.wire.Scalars` | every scalar wire form (varint, zigzag, fixed32/64, float/double, string/bytes), a negative enum value and proto3 `optional` presence |
| `fuzz.wire.Packed` | packed varint, zigzag, fixed, double, bool and enum repetition, an explicitly unpacked field and repeated strings |
| `fuzz.wire.Node` | a recursive message used to reach the nesting limit |
| `fuzz.legacy.Legacy` | proto2 required presence, explicit defaults, explicit packing, a oneof, a map with an enum value and singular message merging |

Unknown field numbers exercise skipping of every wire type, including nested
unknown groups.

For every root, the decode must:

1. Return either a decoded instance or `ProtobufError::InvalidInstance` whose
   path starts with the root's full name. A panic or any other error variant is
   a finding.
2. Stay within the per-input budget below.
3. Re-encode with `format_protobuf::to_vec` and decode back to an equal
   instance.

## Per-input budget

- **Input size:** the target ignores inputs larger than 64 KiB
  (`MAX_INPUT_BYTES`). The smoke run below also passes `-max_len=4096`.
- **Decoded size:** at most `(input bytes + 1) * (largest field count of any
  message + 2)` instance nodes. Each decoded value consumes at least one input
  byte and every group comes from the root or one decoded message value, so a
  bounded schema cannot amplify input by more than this factor.
- **Depth:** at most `2 * (128 + 1)` instance levels, from the decoder's limit
  of 128 nested messages (and 128 nested unknown groups).
- **Time and memory:** smoke and long runs pass `-timeout=10` (seconds per
  input) and `-rss_limit_mb=2048`. libFuzzer reports a slow input or excess
  memory as a crash artifact.

The decoder's own limits (64 MiB messages, 1,000,000 wire fields and 1,000,000
decoded values per call) sit above this harness's input cap; they are not
reached by fuzzed inputs.

## Requirements

- cargo-fuzz 0.13 (`cargo install cargo-fuzz`).
- The nightly toolchain pinned in `rust-toolchain.toml`
  (`nightly-2026-09-07`). Commands run from this directory pick it up
  automatically; from the repository root pass `+nightly-2026-09-07`.

Every command below runs from this directory. `--fuzz-dir .` tells cargo-fuzz
that this directory is the fuzz project.

## Build and smoke run

```sh
cargo fuzz build --fuzz-dir . decode
mkdir -p corpus
cargo fuzz run --fuzz-dir . decode corpus seeds -- \
  -max_total_time=120 -max_len=4096 -timeout=10 -rss_limit_mb=2048
```

`corpus/` is the writable working corpus; `seeds/` is read-only input. Both
`corpus/` and `artifacts/` are ignored by Git. Raise `-max_total_time` for a
longer campaign; keep the other bounds unchanged.

## Reproduce and minimize a finding

libFuzzer writes a failing input to `artifacts/decode/crash-*` (or `timeout-*`,
`oom-*`).

```sh
# Replay one input; the panic message names the root and invariant.
cargo fuzz run --fuzz-dir . decode artifacts/decode/crash-<hash>

# Shrink it to a minimal reproduction.
cargo fuzz tmin --fuzz-dir . decode artifacts/decode/crash-<hash>
```

Copy the minimized input to `regressions/<short-name>.bin`; `cargo test`
replays every file there. Report the defect as a separate issue with that
reproduction rather than fixing the codec in the harness change.

To shrink a grown working corpus: `cargo fuzz cmin --fuzz-dir . decode corpus`.

## Seeds and tests

`seeds/` is generated by `src/seeds.rs`, which builds each input from a small
wire encoder: varint boundaries (ten-byte maximum, overflow, eleven bytes,
truncation), out-of-range integers, non-finite floats, invalid UTF-8,
truncated and boundary-sized lengths (exact, short by one, `u32::MAX`,
`i64::MAX`, `u64::MAX`), packed and unpacked repetition, unknown fields and
groups, field-number limits, oneof switching, duplicate and partial map
entries, and messages exactly at and one past the nesting limit. Regenerate
after changing the generator:

```sh
cargo run --example write_seeds
```

`cargo test` checks that `seeds/` matches the generator, that each seed
reaches its intended success or error, that every prefix of every seed
satisfies the invariants, and that each saved regression still passes. These
tests do not need sanitizer instrumentation.
